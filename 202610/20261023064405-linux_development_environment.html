uv notes

uv is a Rust-based Python package and project manager. See [UV].(https://docs.astral.sh/uv/)

Installation

curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc
uv --version

1. Specifying the Python Version

Python versioning in uv involves two distinct concepts: runtime execution pinning and compatibility constraint definition.

A. Pinning the Active Interpreter (.python-version)

To enforce which Python interpreter uv invokes for the project, pin the version:

# Pin to a minor or patch version (e.g., 3.12 or 3.11.8)
uv python pin 3.12

  • Effect: Writes the version string to a .python-version file in the project root.

  • Interpreter Acquisition: If the requested version is not installed locally, uv automatically downloads and provisions a standalone CPython binary; manual system installation is not required. It can also be explicitly pre-fetched:

    uv python install 3.12

B. Defining Version Constraints (pyproject.toml)

To specify the supported range for users or build systems: * Defined via the requires-python key in pyproject.toml (e.g., requires-python = ">=3.11"). * Can be defined during initialization: bash uv init --python ">=3.11" * Or updated manually inside pyproject.toml.

2. Managing Module Dependencies

uv handles dependency management via atomic operations that update pyproject.toml and synchronize uv.lock and .venv.

A. Adding Dependencies

  • Standard production dependency:

    uv add httpx

  • Version-constrained dependency:

    uv add "pydantic>=2.0,<3.0"
uv add "requests==2.31.0"

  • Package with extras:

    uv add "fastapi[standard]"

  • Development / Test dependencies (Dependency Groups):

    # Adds to [dependency-groups.dev]
uv add --dev pytest ruff

# Adds to a custom named group (e.g., 'docs')
uv add --group docs mkdocs

B. Removing Dependencies

Removes the package reference from pyproject.toml, uninstalls it from .venv, and updates uv.lock:

  • From default dependencies:

    uv remove httpx

  • From a development/specific group:

    uv remove --dev pytest
uv remove --group docs mkdocs

C. Modifying / Upgrading Dependencies

  • Adjusting bounds/constraints: Re-running uv add with a new version constraint overrides the previous entry in pyproject.toml:

    uv add "pydantic>=2.7"

  • Upgrading an existing package to the latest permitted version:

    # Upgrade a single package within pyproject.toml constraints
uv lock --upgrade-package pydantic
uv sync

# Upgrade all project packages within pyproject.toml constraints
uv lock --upgrade
uv sync

  • Direct environment synchronization: To force .venv to reflect the exact lockfile state manually:

    uv sync

3. Contextual Execution: uv run

uv run automatically validates that .venv matches uv.lock, provisions missing dependencies if necessary, injects the correct PATH and environment variables, and executes the target without modifying the host shell state.

  • Direct script execution:

    uv run main.py

    (Or explicitly passing the interpreter: uv run python main.py)

  • Passing arguments to the script: Arguments following the script name are forwarded directly to the Python runtime:

    uv run main.py --input data.csv --verbose

  • Module execution: To execute a module within a package namespace:

    uv run python -m my_package.core

  • Installed console scripts / CLI tools: If a dependency installs an executable binary (e.g., pytest, ruff, or entry points declared in pyproject.toml under [project.scripts]):

    uv run pytest
uv run ruff check .
